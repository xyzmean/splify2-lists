# Свои списки

Один файл — один список. Больше ничего заводить не нужно: сборка сама увидит новый файл и
впишет его в `lists.json`.

## `.lst` — домены и подсети

Пишите как удобно, вперемешку: движок splify2 сам разбирает, где имя, а где адрес. Адресные
строки уходят в набор nftables, доменные — в резолвер.

```
# name: Мой офис
# on: yes

office.example.com
*.corp.example.com
203.0.113.0/24
198.51.100.7
```

## `.asn` — номера автономных систем

Когда у сервиса «свои» сети и перечислять подсети руками бессмысленно. Сборка раз в сутки
спрашивает у RIPEstat, какие подсети анонсирует эта AS, и кладёт результат рядом — в файл
`<имя>.lst`, который попадает в репозиторий и виден в истории.

```
# name: Мой провайдер
AS12345
64500
```

## Шапка файла

Строки-комментарии в начале файла. Все необязательны:

| Ключ | Что значит | По умолчанию |
|---|---|---|
| `name` | как список называется в splify2 | имя файла |
| `about` | одна строка пояснения | нет |
| `on` | `yes` — список включён у нового пользователя | `no` |

Всё остальное после `#` — обычный комментарий, он никуда не уходит.

## Имя файла

Латиница, цифры, `_` и `-`. Имя становится идентификатором списка, а идентификатор уезжает
в настройку роутера — переименование файла выглядит для роутера как «список исчез».
