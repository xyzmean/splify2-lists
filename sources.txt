# Чужие репозитории, из РЕЛИЗОВ которых берутся списки.
#
# Одна строка — один репозиторий. Формат:
#
#     owner/repo | приставка | Название источника
#
#   owner/repo — как на GitHub;
#   приставка  — с неё начинаются имена списков этого источника (itdoginfo:telegram). Нужна
#                по двум причинам: имена у источников совпадают (roblox есть и там, и там), и
#                приставка `itdog` уже занята вторым издателем, зашитым в сам splify2, — с ней
#                он забирал бы себе списки этого каталога и качал их своим тегом;
#   название   — то, что увидит человек в splify2 рядом со списком.
#
# ЧТО ИМЕННО БЕРЁТСЯ: файлы `.srs` из ПОСЛЕДНЕГО релиза. Это наборы sing-box, и splify2
# читает их сам (`steer srs-read` раскладывает набор на домены и подсети). Плоских списков
# в этих релизах нет вовсе, а ветка main — плавающее состояние без версии.
#
# МЫ ИХ НЕ ПЕРЕКЛАДЫВАЕМ К СЕБЕ. В lists.json уходит прямая ссылка на файл релиза с
# ЗАФИКСИРОВАННЫМ тегом — тем, который был последним в момент сборки. Поэтому:
#   * трафик и место чужого репозитория не наши, а список у всех одинаковый;
#   * два роутера с одним lists.json маршрутизируют одинаково;
#   * «откатиться» — это взять прежний lists.json, а не искать, что изменилось внутри.
#
# Убрать источник — закомментировать строку. Добавить свой — дописать строку: сборка сама
# сходит в его релизы. Никакого кода править не нужно.
